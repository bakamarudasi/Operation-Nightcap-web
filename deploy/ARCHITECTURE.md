# アーキテクチャ構想

## ポリシー
- **ユーザー課金はしない**
- 収益モデル: 「面白かったら奢ってね」(投げ銭/サポート)
- ユーザーの個人情報は持たない → セキュリティリスク最小化

## 全体構成図

```
                        ┌─────────────────────────────────────────┐
                        │          CloudFront (CDN)                │
                        │          グローバル配信 + HTTPS           │
                        └──────────────┬──────────────────────────┘
                                       │
        ┌──────────────────┬───────────┼───────────┬──────────────┐
        │                  │           │           │              │
        ▼                  ▼           ▼           ▼              ▼
 ┌────────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
 │ S3         │  │ S3       │  │ EC2/ECS  │  │ EC2/ECS  │  │ S3       │
 │ ホーム      │  │ アセット   │  │ Nightcap │  │ 新ゲーム   │  │ 共有     │

 │            │  │          │  │          │  │          │  │ (将来検討)│
 │ ポートフォリオ│  │ characters/│ │ HTML/JS  │  │ HTML/JS  │  │          │
 │ 奢りリンク   │  │ cards/    │  │ CSS のみ  │  │ CSS のみ  │  │          │
 │ ゲーム一覧   │  │ audio/    │  │          │  │          │  │          │
 └────────────┘  └──────────┘  └──────────┘  └──────────┘  └──────────┘
                                       │
                        ┌──────────────┴──────────────┐
                        │       Route 53               │
                        │       ドメイン管理             │
                        │       例: example.com         │
                        │         ├ /         → S3 (HP) │
                        │         ├ /nightcap → EC2     │
                        │         ├ /game2    → EC2     │
                        │         └ assets.*  → S3      │
                        └─────────────────────────────┘
```

### アセット配信の仕組み
```
ゲームのコード (EC2)          画像・音声 (S3 + CloudFront)
  │                              │
  │  <img src={assetUrl(path)}   │
  │       ↓                      │
  │  VITE_ASSET_CDN 環境変数     │
  │       ↓                      │
  ├── 開発時: "" (ローカル)       │
  └── 本番:  "https://assets.example.com" ──→ CloudFront → S3
```
- EC2は HTML/JS/CSS の配信のみ (軽量)
- 画像・音声は S3 + CloudFront でCDN配信 (高速・安価)
- `src/config.ts` の `assetUrl()` で切り替え

## フェーズ別ロードマップ

### Phase 1: 今 ─ EC2で動かす
```
構成:  EC2 (t2.micro) + Docker + Nginx
コスト: 約¥0/月 (無料枠)
学べる: EC2, セキュリティグループ, SSH, Docker
```
- [x] Dockerfile / docker-compose.yml 作成
- [x] Nginx セキュリティヘッダー設定
- [x] EC2セットアップスクリプト
- [x] fail2ban / SSH強化
- [x] assetUrl() によるCDN切り替え対応 (src/config.ts)
- [ ] 実際にEC2インスタンスを起動してデプロイ

### Phase 2: ホームページ公開 + ドメイン取得 + アセットS3移行
```
構成:  S3 (静的サイト + アセット) + CloudFront + Route 53 + ACM
コスト: 約¥200/月 (ドメイン代のみ)
学べる: S3, CloudFront, Route 53, ACM (SSL証明書), OAC
```
- [ ] ドメイン取得 (Route 53 or 外部レジストラ)
- [ ] S3バケット作成 (ホームページ用 + アセット用)
- [ ] アセットバケットに画像をアップロード (characters/, cards/ 等)
- [ ] CloudFrontディストリビューション設定 (assets.example.com)
- [ ] ACMでSSL証明書発行 (ワイルドカード *.example.com)
- [ ] VITE_ASSET_CDN 環境変数を設定してビルド
- [ ] ホームページ作成 (ポートフォリオ + ゲーム一覧)
- [ ] 「奢り」リンク設置 (OFUSE / Buy Me a Coffee 等)

### Phase 3: Operation Nightcap を本番公開
```
構成:  Phase 2 + EC2 (Docker) + ALB
コスト: 約¥1,500〜2,000/月
学べる: ALB, ヘルスチェック, SSL終端, パスベースルーティング
```
- [ ] ALB設定 (CloudFront → ALB → EC2)
- [ ] ヘルスチェック設定
- [ ] Route 53 でサブドメインまたはパスルーティング
- [ ] HTTPS終端をALBで処理

### Phase 4: 新しいゲームコンテンツ追加
```
構成:  Phase 3 + 追加EC2/ECSコンテナ
コスト: 約¥2,000/月以内を目指す
学べる: ECS, タスク定義, サービスディスカバリ
```
- [ ] 新ゲーム開発
- [ ] ECS Fargate でコンテナ化 (EC2管理不要)
- [ ] ALBのパスベースルーティングで振り分け
- [ ] ホームページにゲーム追加

### Phase 5: 運用成熟
```
構成:  Phase 4 + モニタリング + 自動化
コスト管理が重要
学べる: CloudWatch, CloudTrail, Budgets, Auto Scaling
```
- [ ] CloudWatch ダッシュボード + アラーム
- [ ] AWS Budgets で予算アラート設定
- [ ] CloudTrail で操作ログ記録
- [ ] 必要に応じて Auto Scaling 設定

### 節約テクニック
- EC2は使わない時間帯は停止 (EBS代のみ)
- 静的コンテンツはS3 + CloudFrontに逃がす
- Lambdaの無料枠: 月100万リクエスト
- CloudFrontの無料枠: 月1TBデータ転送
- 将来的にEC2→ECS Fargate→S3に移行してサーバーレス化

## 収益モデル

```
収入源:
  「面白かったら奢ってね」(投げ銭)
  ├── OFUSE
  ├── Buy Me a Coffee
  └── その他サポートサービス

方針:
  ✅ 完全無料で遊べる
  ✅ ユーザー登録不要
  ✅ 個人情報を持たない
  ✅ 楽しんでくれた人が任意でサポート
  ❌ ユーザー課金はしない
  ❌ 広告でユーザー体験を損なわない
```
