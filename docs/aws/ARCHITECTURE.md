# アーキテクチャ構想

## ポリシー
- **ユーザー課金はしない**
- 収益モデル: 「面白かったら奢ってね」(投げ銭/サポート) → **ホームページに設置**
- ユーザーの個人情報は持たない (メアド・名前等は保存しない)
- DynamoDB を使用 (匿名データ + SAA学習目的)

### パスベースルーティング (確定)
- `example.com/nightcap`, `example.com/game2` のようにパスで分ける
- 同一ドメインなので **localStorage を全ゲームで共有** できる
- Vite の `base` オプションでパスプレフィックスを設定

### アセット配信の仕組み
```
ゲームのコード (EC2)          画像・音声 (S3 + CloudFront)
  │                              │
  │  <img src={assetUrl(path)}   │
  │       ↓                      │
  │  VITE_ASSET_CDN 環境変数     │
  │       ↓                      │
  ├── 開発時: "" (ローカル)       │
  └── 本番:  "https://assets.example.com" ──→ CloudFront → S3
```
- EC2は HTML/JS/CSS の配信のみ (軽量)
- 画像・音声は S3 + CloudFront でCDN配信 (高速・安価)
- `src/config.ts` の `assetUrl()` で切り替え

## 共有通貨: 龍門幣 (りゅうもんへい)

```
設計:
  ・全ゲーム共通の通貨
  ・稼ぎ方は各ゲームで独立
  ・正データは DynamoDB に保存 (サーバーサイド検証)
  ・localStorage はキャッシュ + オフラインフォールバック

匿名ユーザー識別:
  ・初回アクセス時に UUID を生成して localStorage に保存
  ・メアド・名前等の個人情報は一切不要
  ・UUID を紛失 (ブラウザ変更等) → 新規扱い (残高リセット)

チート対策 (段階的に実装):
  レベル1: フロントエンド署名検証
    → localStorage のデータにハッシュ付与、改ざん検知
    → 学べる: ハッシュ、HMAC、データ整合性
  レベル2: 暗号化
    → localStorage の値を暗号化して保存
    → 学べる: AES暗号化、Web Crypto API → KMS理解に繋がる
  レベル3: サーバーサイド検証 (本命)
    → API Gateway + Lambda で「+100 龍門幣は妥当か？」を検証
    → DynamoDB に残高保存、クライアントは参照のみ
    → 学べる: API Gateway, Lambda, DynamoDB → SAA-C03 直結

データフロー:
  ゲーム内アクション → Lambda (検証) → DynamoDB (保存) → レスポンス → 画面反映
                                                      ↓
                                              localStorage (キャッシュ更新)
```

## 収益モデル

```
収入源:
  「面白かったら奢ってね」(投げ銭)
  → ホームページ (example.com/) に設置
  ├── OFUSE
  ├── Buy Me a Coffee
  └── その他サポートサービス

導線:
  各ゲーム → 「ホームに戻る」ボタン → ホームページ → 奢りリンク

方針:
  ✅ 完全無料で遊べる
  ✅ ユーザー登録不要
  ✅ 個人情報を持たない
  ✅ 楽しんでくれた人が任意でサポート
  ❌ ユーザー課金はしない
  ❌ 広告でユーザー体験を損なわない
```
