# AWS セキュリティチェックリスト

このプロジェクトのEC2デプロイで学べるAWSセキュリティ知識をまとめました。
**AWS認定 ソリューションアーキテクト Associate (SAA-C03)** の試験範囲に対応しています。

---

## 1. ネットワークセキュリティ (VPC)

### セキュリティグループ (ステートフルファイアウォール)
```
# このプロジェクトの推奨設定:
インバウンドルール:
  - SSH (22)     : 自分のIPのみ (0.0.0.0/0 は絶対NG!)
  - HTTP (80)    : 0.0.0.0/0
  - HTTPS (443)  : 0.0.0.0/0

アウトバウンドルール:
  - すべてのトラフィック: 0.0.0.0/0 (デフォルト)
```

### 試験ポイント
- [ ] セキュリティグループは **ステートフル** (戻りトラフィックは自動許可)
- [ ] ネットワークACLは **ステートレス** (インバウンド/アウトバウンド両方必要)
- [ ] セキュリティグループは **許可のみ** 設定可能 (拒否ルールなし)
- [ ] ネットワークACLは **許可と拒否** 両方設定可能

## 2. IAM (Identity and Access Management)

### このプロジェクトで実践
```
# EC2用のIAMロールを作成 (キーをハードコードしない！)
- EC2にIAMロールをアタッチ
- 最小権限の原則 (必要な権限のみ付与)
- IAMユーザーにはMFA必須
```

### 試験ポイント
- [ ] EC2にはIAMロール (インスタンスプロファイル) を使う、アクセスキーは使わない
- [ ] IAMポリシーの評価順序: 明示的拒否 > 明示的許可 > 暗黙的拒否
- [ ] ルートアカウントにMFAを設定する
- [ ] IAMユーザーではなくIAMロールを可能な限り使う
- [ ] AWS Organizations でSCP (サービスコントロールポリシー) を理解する

## 3. データ保護

### 通信の暗号化 (このプロジェクトで実装済み)
```
- HTTPS (TLS 1.2+) で通信を暗号化
- Let's Encrypt で無料SSL証明書
- HSTS ヘッダーでHTTPS強制
- セキュリティヘッダー設定済み
```

### 保存データの暗号化
```
# EBSボリュームの暗号化
- EC2作成時に「暗号化」をオンにする
- KMS (Key Management Service) で鍵管理
- デフォルト暗号化を有効にする推奨
```

### 試験ポイント
- [ ] EBS暗号化はAES-256を使用
- [ ] 暗号化されたEBSからのスナップショットも暗号化される
- [ ] S3バケットのデフォルト暗号化 (SSE-S3, SSE-KMS, SSE-C)
- [ ] ACM (Certificate Manager) で証明書を無料発行可能

## 4. EC2 セキュリティ

### このプロジェクトで実践済み
```
✅ SSH鍵認証のみ (パスワード認証無効)
✅ rootログイン無効
✅ fail2ban でブルートフォース対策
✅ 自動セキュリティアップデート有効
✅ Nginxのサーバー情報非表示 (server_tokens off)
✅ Dockerでアプリを隔離
```

### 試験ポイント
- [ ] キーペアの秘密鍵は **一度しかダウンロードできない**
- [ ] メタデータサービス (IMDS v2) を使う
- [ ] Systems Manager Session Manager でSSH不要のアクセスも可能
- [ ] EC2 Instance Connect でブラウザからSSH可能

### 試験ポイント

- [ ] VPC Flow Logs: ネットワークトラフィックのログ
- [ ] AWS Config: リソース設定の変更履歴
- [ ] GuardDuty: 脅威検知サービス

## 6. 高可用性 & 耐障害性 (次のステップ)

### このプロジェクトを発展させるなら
```
レベル1 (今ここ):
  EC2 1台 + Docker

レベル2:
  EC2 + ALB (Application Load Balancer)
  → ヘルスチェック、SSL終端

レベル3:
  Auto Scaling Group + ALB
  → 負荷に応じて自動スケール

レベル4:
  ECS Fargate (サーバーレスコンテナ)
  → EC2管理不要

レベル5:
  S3 + CloudFront (静的サイトの最適解)
  → サーバー不要、グローバルCDN
```

### 試験ポイント
- [ ] マルチAZ構成で耐障害性を確保
- [ ] ALBはレイヤー7 (HTTP/HTTPS)、NLBはレイヤー4 (TCP/UDP)
- [ ] Auto Scalingのポリシー: ターゲット追跡、ステップ、シンプル
- [ ] Route 53のルーティングポリシー: シンプル、加重、レイテンシー、フェイルオーバー

## 7. コスト管理 (試験でも重要!)

```
# 無料枠の確認
- Billing ダッシュボードで無料枠の使用状況を確認
- 予算アラートを設定 (Budgets)
- EC2を使わない時は停止する！

# コスト最適化
- リザーブドインスタンス: 1年/3年契約で最大72%割引
- スポットインスタンス: 最大90%割引 (中断あり)
- Savings Plans: 柔軟なコミットメント割引
```

## クイックリファレンス: AWS CLI コマンド

```bash
# セキュリティグループ一覧
aws ec2 describe-security-groups

# インバウンドルール追加 (自分のIPのみSSH許可)
aws ec2 authorize-security-group-ingress \
  --group-id sg-xxxxx \
  --protocol tcp --port 22 \
  --cidr $(curl -s checkip.amazonaws.com)/32

# EBS暗号化をデフォルト有効化
aws ec2 enable-ebs-encryption-by-default

# CloudTrail の状態確認
aws cloudtrail describe-trails
```
